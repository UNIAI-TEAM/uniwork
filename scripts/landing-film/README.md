# UniWork workflow film

Seven-second, silent, looping 3D editorial illustration. Three thin meeting objects gather into a layered shared-context stack and unfold into linked task sheets. The porcelain and anodized metal surfaces use precise bevels, inset faces, backing seams, and small embossed work details. A locally generated softbox environment, physical materials, softened shadows, and ACES tone mapping give the bright studio scene its depth. The film makes no product or customer claims. It is rendered from authored geometry and animation, not generated by a video model.

The authoring project is isolated from the application workspace. Dependencies and intermediate frames live in ignored `.go-tmp/landing-film-runtime`; no root or application dependency files are changed.

From the repository root:

```powershell
node scripts/landing-film/render.mjs --prepare
npm install --prefix .go-tmp/landing-film-runtime
node scripts/landing-film/render.mjs
```

The renderer uses the repository's existing Chromium. On another machine, set `REMOTION_BROWSER_EXECUTABLE` to a Chromium executable. `--previews-only` renders frames 0, 65, 132, and 209 without encoding the video. `npx remotion studio --no-open` from the runtime directory opens the editable composition.

Outputs: `apps/web/public/landing/motion/workflow-film.mp4`, `workflow-film.webp`, and `workflow-film.json`. The manifest records the exact creative prompt, codecs, dimensions, duration, source directory, and SHA-256 hashes. The WebP poster is frame 132. Its EXIF ImageDescription embeds the exact creative prompt, with code-authored attribution in Artist and Copyright; `workflow-film.webp.json` is a readable companion. The renderer checks that the video and poster together stay below 512 KiB.

Animations depend only on Remotion's current frame. Frame 209 matches frame 0, including the waveform, lighting, floating motion, and camera arc. The ending retraces the transformation with an eased return. The renderer uses two concurrent browser tabs and does not need Remotion Studio or either application development server.

## Independent verification boundary

This directory is a standalone authoring tool, not a pnpm workspace package or an application runtime dependency. Its local `package.json` pins the authoring dependencies. `render.mjs --prepare` copies that manifest and the source files into `.go-tmp/landing-film-runtime`; `npm install` creates its dependency tree and lockfile there. The root application lint/typecheck/knip graph excludes this directory, so changes here use the following separate typecheck from the runtime directory after preparing the source:

```powershell
npx tsc --noEmit --skipLibCheck --strict --target ES2020 --module ESNext --moduleResolution Bundler --jsx react-jsx --esModuleInterop src/index.tsx src/workflow-film.tsx
```

Validation for the delivered asset: this typecheck passed; frames 0, 65, 132, and 209 were rendered and visually inspected. Frame 0 and frame 209 had identical SHA-256 hashes. The encoded MP4 was inspected again by decoding its frame at 4.4 seconds, and its WebP poster was viewed. `ffprobe` confirmed H.264, `yuv420p`, 960 by 640 pixels, 30 fps, 210 frames, 7.0 seconds, and no audio stream. The output manifest records the final file hashes. The isolated dependency installation reported zero audit vulnerabilities.
