## No-handler evidence (explicit)

- **No main-process shortcut code in the three app main processes.** `grep -rnE "accelerator|globalShortcut|before-input-event|Menu\.(set|build)" apps/pdf/src/main apps/html/src/main apps/markdown/src/main apps/*/src/preload` → no matches (the `Menu` hits live only in `apps/shell/src/main/index.ts`, `ui-scale-menu.ts`). Menus for these three modules are built by the shell (`buildPdfMenu` 5935, `buildMarkdownMenu` 6018, `buildHtmlMenu` 6117).
- **PDF has no pdf.js viewer key handling.** `pdfjs-dist` (`^6.2.108`) is used only through `getDocument` (`App.tsx:6-8`); `grep -rn "pdfjs-dist/web\|PDFViewer\|EventBus\|pdf_viewer" apps/pdf/src/renderer` → nothing. So no inherited viewer keys (Ctrl+G, F3, N/P, R, Ctrl+Alt+G, presentation mode…): everything is the own handler above.
- **No F-key, Ctrl+Home/End, Ctrl+G, F3 or Ctrl+Y(redo) in PDF**: all modifier combos not listed return at `App.tsx:6372`.
- **HTML source editor has no search keymap**: `cm-setup.ts:119-125` lists closeBrackets, default, history, fold, indentWithTab only; find/replace is the host `FindPanel`.

## Structural findings

1. **No shared key table in any of the three modules.** Docs has `shortcuts.ts` as a single list (other assignment); pdf/html/markdown define bindings inline in `App.tsx` and hint strings separately, so a key change needs edits in handler, shell menu and i18n.
2. **Two layers on the same keys.** Save, Save As, Print, Open, Close are bound both as Electron menu accelerators (`index.ts:5944-5995`, `6027-6094`, `6126-6186`) and in the renderer (`pdf App.tsx:6349/6359`, `html App.tsx:1498`, `markdown App.tsx:1076/1079`). Ctrl+O and Ctrl+W/Ctrl+Shift+H exist **only** in the shell menu: they do nothing in the web frame. Print in HTML has no renderer binding on desktop (`App.tsx:1485-1486`); on web it is added by `installPrintAccelerator` (`web/modules/html/webapi.ts:67`) and by the inspector relay (`inspector.js:970`).
3. **PDF Ctrl+Shift+S mismatch.** `pdf App.tsx:6349` matches `k==='s'` without a shift check and runs plain `save()`, while the menu binds Ctrl+Shift+S to Save As (`index.ts:5964`). HTML and Markdown test `event.shiftKey` and call `doSave('saveAs')`. Likely shadowing of Save As on desktop PDF (not run).
4. **PDF redo**: renderer redo is Ctrl/Cmd+Shift+Z only; Ctrl+Y is not bound there, but the Edit-menu `redo` role (Electron default) uses Ctrl+Y on Windows and would redo the web contents, not the PDF history (reasoning from role defaults, medium confidence).
5. **Keys forwarded across a frame boundary (HTML).** The preview iframe forwards only print (when claimed), undo/redo, zoom, Delete/Backspace, arrows, Esc, Ctrl+K (Ask AI), Ctrl+B/I, Alt+Up/Down (`inspector.js:970-1058`). Ctrl+S, Ctrl+F, Ctrl+H and Ctrl+\\ are not forwarded, so with focus inside the preview those keys go to the iframe/browser.
6. **Markdown Ctrl+E conflict.** App's capture handler (`App.tsx:1090`) toggles source view and calls `preventDefault`; TipTap's inline-code default `Mod-e` sits behind it, and `Mod-Shift-s` (strike default) loses to Save As (`App.tsx:1076`). In Word, Ctrl+E is centre align and Ctrl+D is Font; Markdown uses Ctrl+D for Duplicate block (`blockKeymap.ts:13`) and Ctrl+K opens `window.prompt` (`blockKeymap.ts:23`). Ctrl+Shift+Up/Down move blocks (`blockKeymap.ts:16-17`), shadowing paragraph-wise selection.
7. **IME.** Only the AI popovers, edit-queue cards, server-comments Esc and the CodeMirror redo handler check `isComposing` / `keyCode===229`. The global handlers are not guarded: pdf/html/markdown `App.tsx` window handlers (modifier combos, so low practical risk), PDF dialog `Enter` handlers (`App.tsx:9734-9925`, `PasswordDialog.tsx:74`, `SignatureDialog.tsx:362`) and the markdown slash menu `Enter` (`SlashMenu.tsx:40`) can fire on an IME commit Enter. Escape cascades (`pdf App.tsx:6375`, html present-mode `App.tsx:1201`) do not guard `isComposing` either (the inspector does, `inspector.js:1037`).
8. **AltGr.** HTML and Markdown global handlers exclude `altKey` (`App.tsx:1496`, `1074`) so AltGr is safe; PDF `App.tsx:6347-6372` and Markdown `mathEdit.ts:123`, HTML `StylePanel.tsx:354` do not exclude Alt (Ctrl+Alt ≡ AltGr on Windows).
9. **`key` vs `code`.** All three use `event.key` (lowercased); no `event.code`, so layout-dependent keys such as `=`/`+`/`-`/`\\` match the produced character, not the physical key.
10. **In-app hints.** Only five (pdf) / two (html, markdown) shortcuts are shown anywhere; none comes from the handler table. The ribbon tooltips use `data-tip`.
