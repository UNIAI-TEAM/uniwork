## Structural findings

1. **Docs hint table and handlers are separate, but hints for the dialog come from one table.** `ShortcutsDialog` renders `SHORTCUTS` + `shortcutKeys()` (Mac notation rewritten by `macShortcutsToWin`/`platformShortcuts`, `packages/i18n/src/index.ts:137-159`); a test is said to guard drift (header comment, not run). Other docs hints are separate literals: ribbon tooltips are i18n strings with ⌘ glyphs rewritten at lookup (`createI18n`, `i18n/src/index.ts:219`); context-menu keys are literals in `ContextMenu.tsx:397-762` passed through `platformShortcuts`; File-menu hints in `Ribbon.tsx:2061-2116` are hard-coded `Ctrl+…` (no Mac form). Other modules: hints are hand-written strings, none derived from handlers (see part files).
2. **Duplicate registrations in docs (menu accelerator + renderer + TipTap).** Save, Open, Find, Go To, Font ⌘D, Paragraph, Link ⌘K each exist in the menu (desktop) and in `App.tsx` (desktop and frame). Bold/Italic/Underline exist in the menu (`docs-main.ts:6249-6253`) and TipTap (`marks.ts`). Undo/Redo: menu `6152/6155` + TipTap `UndoRedo`; **Ctrl+Y exists only via TipTap**.
3. **Menu-only keys do not exist in the web frame.** No keyboard→menu mapping was found for docs (`web/docs/bridge` has only the print accelerator and the Esc forwarder). So in the frame these have no handler: Ctrl+N, Ctrl+Shift+N, Ctrl+W, Ctrl+/ (shortcuts sheet), Ctrl+=/−/0 zoom (browser page-zoom would apply instead), Ctrl+Shift+V paste-match (browser-native). Ctrl+P is added by `web/docs/bridge/print-accelerator.ts` (docs + html only). Sheets and slides get Ctrl+S/Ctrl+Shift+S/Ctrl+O in the frame from their own bridge handlers (`web/modules/sheets/bridge.ts:524`, `web/modules/slides/web-slides-api.ts:858`). For pdf/html/markdown the same Ctrl+O and Ctrl+W exist only in the shell menu. (Inference from grep of `web/` and the renderers; no run.)
4. **Keys forwarded frame → host: only Escape.** `installEscapeForwarder` (`web/docs/bridge/escape-forwarder.ts:34-60`, installed `install.ts:134`, `module-bridge.ts:230`) sends `close_requested{reason:'escape'}` for an unhandled Esc, with `isComposing`, `keyCode 229`, `repeat`, `defaultPrevented` and dialog/menu/`[data-esc-local]` guards. Docs `read-mode-escape.ts` is the matching capture-phase handler that runs first. No other key is posted to the host. (HTML's preview iframe forwards keys to its own app by `postMessage`, not to the UniWork host.)
5. **Conflicts between layers (docs).** TipTap core `Mod-Enter` (exitCode) is shadowed by `WordEditorShortcuts` `Mod-Enter` = page break (`extensions.ts:1668`); the page-break accelerator is deliberately kept out of the menu so renderer inputs can use Ctrl+Enter (`docs-main.ts:6232`). `Ctrl+Shift+V` is the Electron `pasteAndMatchStyle` role on desktop, so Word's paste-format chord is moved to Ctrl+Alt+Shift+V (`Ribbon.tsx:1850`, `shortcuts.ts:88-94`). Renderer Save handler tests `e.key==='s'` so Shift+S never reaches it; Save As works on desktop through the menu only. PDF is the reverse: its renderer treats Ctrl+Shift+S as plain Save (`pdf App.tsx:6349`), shadowing the menu's Save As.
6. **Differences from Microsoft 365 visible in the code (for later stages):** docs Paragraph dialog Ctrl+Alt+M (Word: comment); subscript Ctrl+, (Word Ctrl+=); indent Ctrl+M on Mac is Control; endnote/footnote/comment ⌥⌘ chords are Word-for-Mac; Ctrl+Shift+8 and Ctrl+8 both toggle marks; Ctrl+Space clear formatting matches Word; markdown Ctrl+E (source toggle) / Ctrl+D (duplicate block) / Ctrl+K (prompt link) collide with Word's centre / Font / hyperlink; slides Ctrl+K opens AI ask (PowerPoint hyperlink); sheets Ctrl+Shift+T AutoSum and Ctrl+Shift+V paste values are not Excel bindings. Details in the part files.
7. **IME safety is poor across the board.** Only a few handlers check `isComposing`/229: docs ribbon font box (`Ribbon.tsx:1423,1436,3452`), docs AI popovers, `packages/ui` AiComposer (`:233`), AiQueueStrip (`:195`), CollabComposer (`:406`), the Esc forwarder, HTML inspector. Docs `App.tsx` window handler is chord-only (low practical risk) but the plain-key handlers (read-mode Esc, hf-editor Esc, auto-link Space/Enter `extensions.ts:6738`, find/prompt Enter) and nearly all dialog Enter handlers in sheets/pdf have no guard — relevant for Vietnamese Telex/VNI. TipTap/ProseMirror keymaps are IME-guarded by ProseMirror itself (not verified here → `unknown`).
8. **AltGr.** Docs window handler: chords with `!e.altKey` are AltGr-safe; the ones that require mod+alt (Paragraph dialog, style 1-3, comment, footnote/endnote, Ctrl+Alt+Shift+V) fire on AltGr+key on Windows (`altgr_ok=no`). Save/Open/Find lack `!altKey`. Sheets layer 1 excludes Alt except Paste Special; pdf has no Alt exclusion; html/markdown global handlers exclude it.
9. **`event.key` vs `event.code`.** Docs mixes both: letter chords use `e.key` (layout-dependent), punctuation/digit chords use `e.code`. Sheets layer 1 uses `e.code` (+ raw keyCode in Univer registrations). Slides, pdf, html, markdown use `e.key` only.
10. **Ribbon collapse is shared** (`packages/ui/src/ribbon-collapse.tsx`, window keydown, in all six modules): Ctrl+F1 / ⌥⌘R; compact ⌥⌘K / Ctrl+Alt+K only in docs (only docs passes `compact`).

- Every one of the six modules has handlers; none is without shortcuts.
