# UniWork Office desktop inventory (G4-01a / UNI-830)

**Status:** inventory input for G4-D1, G4-D2 and G4-D3. The identity values in the companion JSON are **proposed**, not an accepted ADR or a build decision.

## Scope and evidence method

This lane inspected the read-only `genoffice` checkout, the committed `packages/office-upstream` selection, the G0 source manifest, and the G1/G2 packaging hand-off. Source inspection is labelled **read**; command results are labelled **run**. No upstream source was copied, symlinked, or added to this repository. The external checkout is provenance only; product-facing names in this document are UniWork names.

The lane began at repository `HEAD 904c473a284493f95ba3e82084e741c1d1656a10` on branch `feature-UNI-830-office-desktop-inventory`. The required worktree bootstrap ran with `bash scripts/init-worktree-env.sh .env.worktree`; Node `v22.23.2` and pnpm `10.28.2` were used for the install.

## Findings at a glance

* **No existing UniWork desktop fork is present.** `packages/office-upstream` is a private, Apache-2.0-attributed engine source package. Its frozen `upstream/` tree has 767 files and the provenance checker proves every recorded blob matches commit `09485f884dc845cf3bf27fb7edfe489f9d457aad`; it has no `apps/shell`, no desktop package, and no `src/preload` tree.
* **The upstream shell is a real Electron host, but it is not a reusable product host.** It wires six module runtimes, filesystem/process/native handles, an XLSX sidecar, account/cloud integrations, MCP/control surfaces, analytics, and an auto-updater. Its app id, user-data, schemes, URLs, and credentials are upstream-owned and must not be inherited.
* **The G2 hand-off is the reusable boundary.** Desktop consumers should use `@uniwork/office-engine/desktop` and `@uniwork/office-contracts`; the renderer receives typed host capabilities, while main owns local I/O, native handles, secrets, deep links and sidecar lifetime. No path, token, file handle or generic HTTP/exec capability crosses the renderer boundary.

## Recommendation input for G4-D2 (not a decision)

**Recommendation:** build a new Electron host around the G2 source pin and its typed desktop engine entrypoint rather than reuse the inspected shell as a fork. The existing UniWork package is an engine subset without shell/preload/renderer code; copying the complete shell would also copy an incompatible product identity, upstream auth/cloud, updater/feed, analytics, MCP/control surfaces and host-specific assumptions. A new host keeps the six editor adapters and `@uniwork/office-contracts` at the G2 boundary while making main/preload/renderer, native sidecar, secrets, local files and deep links explicit UniWork-owned surfaces.

The boundary implied by this recommendation is:

* **Renderer:** shared G3 Office views plus core/runtime/navigation/transport adapters; sandboxed, context-isolated, Node-disabled; no database, filesystem, process, secret, token or native handle.
* **Preload:** a small typed allowlist only; no `ipc.invoke(channel, arbitraryArgs)`. Main validates sender/frame/origin, session generation, schema, scope and byte limits.
* **Main:** DOC-005 desktop auth, UniWork transport allowlist, user-data/draft namespace, local-file intent, native sidecar lifecycle, deep-link registration and window policy. Native operations take opaque operation/handle values, never renderer-supplied shell commands.
* **Engine:** use `@uniwork/office-engine/desktop` and contracts from the G2 hand-off. Keep XLSX recalc as the Rust sidecar owned by the host/service; do not place `convert/native` or sidecar handles in a browser bundle.
* **Packaging/update:** consume only the proposed identity manifest and a UniWork-owned channel after G4-D1/D3; preserve LICENSE/NOTICE and regenerate third-party notices at release.

This is an input to G4-D2. It does not select Electron libraries, credential-store APIs, lock/recovery semantics, OS support, signing, or an update provider.

## Verification limits and out-of-scope items

* This slice read source and ran the vendored integrity check, the worktree install, and a deliberately blocked `--skip-install` build attempt. It did **not** claim an Electron build, installer, code-signing, browser, macOS, Safari, OCR, or native sidecar result.
* The G2 clean-checkout proof remains limited to its recorded lab evidence; a full engine build still needs the prepared source/dependencies and fixtures named by that hand-off.
* No `apps/office-desktop` code, package/lockfile change, or ADR was created. The ADR belongs after G4-D2 selects the host.
* No `../genoffice` build assumption is allowed. Any future scratch build must copy the pinned vendored selection, install dependencies inside that scratch directory, apply the numbered patches, and record artifact hashes.
