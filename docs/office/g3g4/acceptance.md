# Office G3/G4 acceptance matrix

This is the QA matrix for **UNI-829** (G3-10a) and **UNI-837** (G4-08a matrix slice). It is a planning artifact: every row is `not_run` until a Tester records evidence on the final lane revision, except rows held by a decision gate, which are `blocked` with an owner and evidence path (today only `G4-A14`). The machine-readable source is [capability-rows.json](./capability-rows.json).

## Inventory and counts

The pinned inventory revision is `09485f884dc845cf3bf27fb7edfe489f9d457aad`. It contains **95 capability rows**, of which **72** have `mustPort: true` and are the Q1-B rows represented here; 23 rows are outside Q1-B (ADV-002, OCR, or explicitly not pilot). This records the actual inventory instead of assuming the plan's earlier 95-row capability count is the matrix scope.

The fixture source is `09485f884dc845cf3bf27fb7edfe489f9d457aad` in [the pinned G0 manifest](../g0/fixtures/manifest.json). Hashes are copied exactly, including `null` for the two large-band fixtures whose committed manifest intentionally records no hash; no row with a null-hash fixture is marked `pass`. No G0 fixture or evidence-register entry is edited.

## Row contract

Each row has a unique `id`, an owner task, host (web, desktop, or both for shared capability/error rows), one of the allowed oracle types (`object/part`, `extraction`, `render diff`, `receipt`), fixture id and manifest SHA-256, required negative cases, reviewer gate, and status. A row may become `blocked` only with `blockedOwner` and `evidencePath`; no row is `pass` in this slice. Plan Section 7.3 maps a required row that has not run at acceptance to `blocked`, so the machine-readable matrix records the unblock owner and where the evidence will land.

For Q1-B capabilities, the owner pair maps the same inventory row to the web format task and the desktop format task. Baseline fields retain G1/G2 limitations: `not_bound` means the provider has not bound that operation, while `to_re_run` means the prior evidence must be repeated on the final host/revision.

## Decision gates

The 2026-09-29 user gate decisions are applied here. Reviewer cells stay `pending G3-D3` / `pending G4-D3` until a reviewer is named; no gated claim is resolved by a default. Gate G4-D3 keeps release-side rows blocked: `G4-A14` (installer namespace, signature/feed, upgrade/rollback) is `blocked` until the G7 decision provides certificates and the update distribution.
