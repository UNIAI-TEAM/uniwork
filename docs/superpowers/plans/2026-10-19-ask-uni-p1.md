# Hỏi UNI v2 — P1 Agent đọc: Implementation Plan

> **Trạng thái:** in-progress — kế hoạch chờ chủ sản phẩm duyệt, chưa code. Issue UNI-1962 (cha: epic F-09, tiếp nối UNI-1818).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hỏi UNI thành agent chỉ đọc. Model tự gọi tool để đọc dữ liệu workspace, qua quyền của người hỏi, trong nhiều vòng. Câu trả lời viết bằng markdown, có trích dẫn `[S#]` giữ nguyên số trong cả hội thoại. Người dùng chọn được model Claude và mức nỗ lực. Tất cả nằm sau flag `ask_uni_agent`.

**Architecture:**
- Vòng agent đặt ở `server/internal/service/askuni_agent.go`. Mỗi vòng là một lời gọi `gateway.Complete`. Lượt đầu render prompt `copilot_answer@2`; các lượt sau là `ToolResultTurn`.
- Tool đọc gọi thẳng các phương thức đọc của `McpToolService`; các phương thức này đã kiểm quyền bằng `Human(user)`. Server tự gắn workspace.
- Kết quả tool thành các nguồn đánh số `S#`, bọc trong `<untrusted>`.
- Provider Anthropic thêm effort, strict tool, prompt caching, và giữ nguyên block thinking giữa các vòng.
- Gateway nhận model, effort và run id do caller chọn, và tính giá cả token cache.
- Flag tắt thì luồng P0 chạy như cũ.

**Tech Stack:** Go (Chi, pgx, sqlc, `github.com/anthropics/anthropic-sdk-go` v1.68.0), PostgreSQL, Redis, Prometheus.

**Spec:** `docs/superpowers/specs/2026-10-16-ask-uni-agent-design.md` — các mục §6.1, §6.2, §6.3, §6.6, §6.7, §6.11 (#3, #7, #8), §7 P1, §8, §9.

## Quyết định khi viết kế hoạch

Spec §11 để những điểm này cho người xây dựng. Mỗi mục ghi quyết định, lý do, và cái giá phải trả nếu quyết định sai.

- **R1 — Phần việc chia theo provider.**
  - Quyết định:
    - Production đang gọi thẳng Anthropic (Task 10 của P0, `AI_PROVIDER=anthropic`); router chưa có.
    - Provider `anthropic` làm đủ: effort, prompt caching, giữ thinking.
    - Provider `openai` chỉ thêm `strict`.
    - Effort, caching và `reasoning_details` qua router làm khi có router, đúng chữ "chờ" ở §6.7.
    - Danh mục model và bảng giá chỉ khai báo tên model của Anthropic. Tên model phía router thêm bằng một migration khi router công bố danh sách cố định.
  - Giá nếu sai: chuyển production sang router cần một PR nhỏ.
- **R2 — Số `S#` ổn định trong hội thoại.**
  - Quyết định:
    - Dựng lại số từ các trích dẫn đã lưu trong `ai_messages` của hội thoại.
    - Đọc bằng một query riêng, không giới hạn 200 dòng.
    - Nguồn đã từng trích giữ số cũ. Nguồn mới lấy số lớn nhất + 1.
    - Không thêm bảng.
  - Lý do: câu trả lời cũ chỉ chứa những số đã trích.
  - Giá nếu sai: nguồn chưa từng trích có thể đổi số giữa các lượt. Vô hại, vì số đó không nằm trong câu trả lời cũ nào.
- **R3 — Capability, prompt và model Tự động.**
  - Thêm capability mới `copilot_agent` với policy riêng: `MaxTokens` 4096, temperature 0. Prompt mới là `copilot_answer@2`; v1 giữ nguyên.
  - Model Tự động là model mặc định của capability. Với anthropic, đó là `claude-sonnet-5-5`.
  - Biến `AI_MODEL_COPILOT_AGENT` chỉ đặt model Tự động (§6.11 #8).
  - Production đang đặt `ANTHROPIC_MODEL=claude-sonnet-5`, biến này đè mọi capability. Vì vậy deploy env thêm `AI_MODEL_COPILOT_AGENT=claude-sonnet-5-5`.
- **R4 — Mức nỗ lực.**
  - Tự động là `medium`, luôn gửi giá trị tường minh.
  - Người dùng chọn được `low`, `medium` hoặc `high`. Không bao giờ gửi `xhigh` hay `max`.
  - Chỉ gửi effort cho model nhận được tham số này.
- **R5 — Các tham số không gửi.**
  - Không gửi `thinking` (model 5.5 tự chạy adaptive), không gửi `budget_tokens`.
  - Không gửi `temperature`: policy đặt 0 và `anthropicAcceptsSampling` đã chặn.
  - Để trống `tool_choice`, nghĩa là `auto`.
  - Không dùng `fallbacks` (beta) ở P1. Model từ chối thì lưu câu trả lời có notice `refused`.
- **R6 — Schema tool strict.**
  - Schema tool của Hỏi UNI viết riêng, chạy strict: mọi thuộc tính nằm trong `required`, có `additionalProperties:false`.
  - "Bỏ trống" là `""`, `false` hoặc `0`, không dùng `null`. Cách này hợp lệ với strict của cả Anthropic lẫn OpenAI.
  - Không có thuộc tính `workspace_id`.
- **R7 — Tool đọc dùng chung với MCP.**
  - Tool gọi thẳng phương thức đọc của `McpToolService`, với `McpPrincipal{UserID, OrganizationID}` dựng từ `ai.ToolContext`. Workspace lấy từ `tc.WorkspaceID`.
  - Ba tool chỉ Hỏi UNI có: chat, thành viên, khối lượng việc.
  - `list_tasks` của MCP nhận thêm các bộ lọc mới, dùng cùng câu SQL.
- **R8 — Định nghĩa quá hạn.**
  - Quyết định: `due_date` trước hôm nay (theo UTC, giống P0), và trạng thái không thuộc category `done`/`cancelled` của `task_statuses`. Điều kiện tính trong SQL.
  - Giá nếu sai: `searchWorkItems` của P0 vẫn so `status != "done"`. Chỉ thứ hạng kết quả tìm kiếm bị ảnh hưởng, để nguyên.
- **R9 — `authored_by_asker` để sang P3.**
  - Quyết định: cờ này chỉ có tác dụng ở P3, khi nó hạ quyền một lượt bị nhiễm. Ở P1, mọi kết quả tính là "không rõ" = false, đúng quy tắc §6.3.
  - Lý do: P1 chỉ có tool đọc, nên cờ không đổi gì.
- **R10 — Giới hạn một run.** Đây là giá trị bắt đầu, chỉnh theo kết quả eval.

  | Giới hạn | Giá trị |
  |---|---|
  | Số vòng tool | 4 |
  | Lời gọi tool mỗi vòng | tối đa 6 |
  | Ngân sách token cả run | 60k vào / 4k ra; vượt thì vòng kế là vòng trả lời |
  | Mỗi kết quả tool | 64 KB |
  | Deadline run | 120s; còn dưới 40s thì vòng kế là vòng trả lời |
  | Run đồng thời mỗi tổ chức | 8 (lease Redis như UniWork AI) |
  | Lời gọi model mỗi tổ chức | 600 mỗi phút |
  | Câu hỏi mỗi người | giữ 20 câu mỗi phút |
  | `max_tokens` mỗi lời gọi | 4096 |

- **R11 — Vòng trả lời bắt buộc và thử lại.**
  - Ở vòng trả lời bắt buộc, cuối kết quả tool cuối có thêm một dòng nhắc trả lời ngay, không gọi tool.
  - Vẫn gửi tools, vì lịch sử đã có `tool_use`.
  - Trả sai định dạng nghĩa là một trong ba trường hợp:
    - rỗng sau khi gỡ thẻ;
    - bị cắt ở `max_tokens`;
    - vẫn gọi tool.
  - Khi sai định dạng: thêm một lượt user nhắc định dạng (`Continuation`) và thử lại một lần. Vẫn sai thì lưu notice `agent_failed`.
  - Mọi lời gọi đã chạy đều tính tiền.
- **R12 — Token cache.**
  - `ai_usage_events` thêm `run_id`, `cache_read_tokens`, `cache_write_tokens`.
  - Giá cache tính theo giá input: đọc bằng 10%, ghi (cache 5 phút) bằng 125%. Không thêm cột giá.
  - Quota token tính cả token cache, tức đếm mọi token đã xử lý.
- **R13 — Không đổi client ở P1.**
  - Notice mới `agent_failed` và `refused` hiện bằng nhánh `default` có sẵn (`notice.unavailable`).
  - Câu trả lời markdown hiện dạng chữ thô trong panel P0 cho đến P2.
  - Flag mặc định tắt, nên chỉ tổ chức được bật mới thấy.
- **R14 — Bật/tắt model theo tổ chức.**
  - Lưu ở cột `organizations.ask_uni_models TEXT[]`. NULL là mặc định: Haiku và Sonnet bật.
  - API admin: `GET/PUT /orgs/{org}/ai/ask-models`.
  - Giao diện admin và menu chọn model làm ở P2, cùng ô nhập mới (§5.1).
- **R15 — Issue và nhánh.** Một issue UNI-1962 cho cả P1, một nhánh, nhiều commit, không tách sub-issue.
- **R16 — Giá model.** Theo tài liệu Anthropic (bản cache 2026-10-06), khớp spec §6.6.

  | Model | Giá vào / ra mỗi triệu token |
  |---|---|
  | Opus 5.5 | $4 / $20 |
  | Sonnet 5.5 | $2 / $10 |
  | Haiku 5.5 | $0.10 / $0.50 (cho prompt ≤ 100K token; run P1 không vượt mức này) |
  | Opus 5 (sửa giá cũ) | $5 / $25 |
  | Sonnet 5 (sửa giá cũ) | $2 / $10 |

  - Giá cũ sửa bằng một hàng mới có `effective_at` mới, vì bảng lưu lịch sử giá.
  - Người làm Task 2 kiểm lại trang giá chính thức trước khi ghi. Nếu lệch thì dùng giá trang chính thức và ghi vào ledger.
